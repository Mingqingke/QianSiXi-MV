## 3. 校准状态：哪些是硬的，哪些还要你确认

**硬的（已核实）**
- 总时长 239.3 s、帧数 7179 帧
- 每一句唱词的开始时间（来自带时间戳的 LRC，40 条齐全）
- 21.65 s 前奏、21.92 s 大间奏、13.96 s 尾奏这三个"无唱词窗口"

**要你确认的**
1. **你的音频是否同一母版**：如果本地文件的时长不是 239.30 s（例如 238 / 240），
   那么整条 LRC 会整体偏移。改 `src/timeline.ts` 的 `AUDIO.durationSec`，
   并在 `src/lyrics.ts` 里加一个全局 `OFFSET`（秒）即可，不用逐句改。
2. **逐句时间戳的精度**：平台 LRC 是逐句级别（不是逐字），所以字幕按"整句显示 +
   演唱结束退场"设计，不做卡拉 OK 式逐字上色——这也和"禁止廉价卡拉 OK 效果"一致。
3. 若你手上有更准的 LRC/SRT（比如官方发行版附带的），直接替换
   `src/assets/qiansixiLrc.ts` 里那段原文，其余全部自动生效。

## 4. 渲染端必须注意：中文字体

GitHub Actions 的 `ubuntu-latest` **不含中文字体**，字幕会渲染成豆腐块。
字幕上场前需要在工作流里补一步（二选一）：

```yaml
- run: sudo apt-get update && sudo apt-get install -y fonts-noto-cjk   # ~100MB，最省事
```

或把一份子集化的思源宋体放进仓库 `public/fonts/`，在 `src/theme.ts` 里指定
`@font-face`（`@remotion/fonts` 的 `loadFont()`），这样字体不会随机器变化。

## 5. 后期配乐对齐说明（给你的流程）

1. 交付视频是**无音轨**的，第 0 帧 = 原曲第 0 秒；
2. 总帧数 7179、帧率 30fps、时长 239.300 s —— 与母版 239.3 s 完全一致；
3. 剪辑软件里把原曲拖到 0 帧对齐即可，**不要拉伸、不要变速**；
4. 若你的音频比 239.30 s 长/短哪怕是 0.2 s，都说明不是同一母版，
   回来改 `AUDIO.durationSec` 重渲一次（全片重新按新总长铺满）。
